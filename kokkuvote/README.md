# Kokkuvõte ja refleksioon

## a) Mis on Git ja miks seda kasutatakse?

Git on versioonihaldussüsteem, mis võimaldab jälgida kõiki muudatusi failides. Seda kasutatakse selleks, et töötada meeskonnas, näha ajalugu, vajadusel naasta vanema versiooni juurde ja hallata erinevaid arendusharusid. Ilma Gitita oleks koodi või dokumentide kooskõlastamine väga keeruline.

## b) Mis vahe on commitil ja pushil?

Commit salvestab muudatused kohalikku repositooriumisse koos kirjeldava sõnumiga. Push aga saadab need commited üles GitHubi (kaugrepositooriumisse), et need oleksid teistele kättesaadavad. Commit on nagu foto hetkeseisust, push on nagu foto üleslaadimine pilve.

## c) Miks on harud (branches) kasulikud?

Harud võimaldavad arendada uut funktsionaalsust või katsetada ideid ilma peamist (main) haru rikkumata. Kui muudatused on valmis, saab need läbi Pull Requesti põhiharuga liita. See on väga kasulik meeskonnatöös ja vigade vältimisel.

## d) Mis on Pull Request ja milleks seda vaja on?

Pull Request on ettepanek viia muudatused ühest harust teise. Enne liitmist saab koodi üle vaadata, arutada ja vajadusel parandusi teha. PR on hea viis kvaliteedi tagamiseks ja teadmiste jagamiseks meeskonnas.

## e) Mille poolest erineb Git kõigest muust (nt failide kopeerimisest USB-le)?

Failide kopeerimine USB-le ei hoia ajalugu, ei võimalda koostööd ja on väga vigadele altid. Git aga mäletab iga muudatust, kes selle tegi ja miks. USB-ga on lihtne kirjutada üle teiste muudatusi – Gitiga seda juhtuda ei saa.

## f) Kuidas seostub Git projektijuhtimisega (Issues = ülesanded, Kanban = Projects)?

GitHubis saab Issues luua ülesandeid, veateateid või ideid. Neile saab määrata teostajaid, silte ja prioriteete. Kanban (Projects) võimaldab neid ülesandeid visuaalselt hallata (nt: To Do, In Progress, Done). See on otsene seos projektijuhtimisega.

## g) Kas hakkaksid GitHubi edaspidi kasutama? Milleks?

Jah, kindlasti. Ma kasutaksin GitHubi oma projektide hoidmiseks, koodi jagamiseks teistega ja meeskonnatööks. Samuti saab seal hoida dokumentatsiooni, teha oma portfoolio ja õppida teiste projektidest.

## h) Mis oli selle töö juures kõige raskem ja kõige lihtsam?

Kõige lihtsam oli luua repositoorium ja lisada faile. Kõige raskem oli alguses aru saada harudest ja Pull Requestitest – kuid kui ühe korra ära tegin, siis sain loogikast aru. Samuti oli vaja harjutada häid commit sõnumeid.

## Minu üldine mulje

See töö andis mulle väga praktilised teadmised Gitist ja GitHubist. Varem ma ei kasutanud versioonihaldust, nüüd tunnen, et olen valmis kasutama seda reaalsetes projektides. Olen rahul, et sain kõik sammud ise tehtud.
